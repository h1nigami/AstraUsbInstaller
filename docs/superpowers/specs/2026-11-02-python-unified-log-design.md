# Единый журнал Python-станции

Пользователь не может выполнять команды на станции. Для диагностики обновления достаточно одного `astra-usb-monitor.log` в корне архива или его копии через «Выгрузить логи», без подпапок и дополнительных файлов.

Используется существующий файловый журнал, Python stdlib и systemd. Апдейтер включает запись до проверки релиза. Вывод установщика, проверки импорта и отката попадает в тот же журнал, включая вывод при таймауте. На запуске станции, в конце попытки обновления и при экспорте автоматически добавляются версия, сбойный тег, состояния и последние сообщения обеих служб, а также последние сообщения ядра об USB, дисках и завершении процессов. Ошибка диагностики не мешает работе станции и обновлению. Команды имеют таймауты, объём системных выдержек ограничен.

Существующий запасной журнал используется, пока диск архива недоступен. При возвращении архива накопленный текст добавляется в основной журнал без удаления исходника, чтобы параллельный апдейтер не потерял свои записи. При экспорте включается и оставшийся запасной журнал. Повторное включение старого фрагмента допустимо и обозначается заголовком источника. Журнал не очищается откатом кода. Время, PID и версия помогают различать сеансы. Экспорт возвращает один файл с уникальным именем прямо в выбранном каталоге.

Рассмотрены отдельный сервис-сборщик и замена существующего журнала на journald. Они требуют новых служб или меняют запись на Windows. Расширение текущего журнала сохраняет установку и формат. Системные выдержки являются снимками при перечисленных событиях, непрерывная запись всего журнала ОС не требуется. Семейства релизов, механизм отката, архивы, база и настройки не меняются.
