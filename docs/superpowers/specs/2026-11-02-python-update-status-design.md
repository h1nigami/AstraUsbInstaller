# Результат обновления в интерфейсе

Вместо постоянной надписи «Проверка обновления запущена» раздел «О программе» показывает состояние службы, последние два сообщения апдейтера и время последнего сообщения. Видны доступная версия, загрузка, установка, проверка запуска, успешное завершение, откат и причины пропуска. Данные поступают из systemd и journald, которые уже используются на станции, без нового файла состояния.

Чтение выполняется в фоновом потоке с таймаутами команд. Изменения Tk передаются через root.after, старые запросы не могут затирать новый результат. До запуска проверки запоминается предыдущее время запуска службы; устаревший результат не выдаётся за ответ новой попытки. Если служба не начала попытку за 15 секунд, это показывается явно. Запросы после закрытия GUI прекращаются. При запуске GUI восстанавливается результат последней проверки, включая работающий апдейтер, который перезапустил интерфейс.

Считываются только сообщения текущей загрузки ОС и текущего запуска службы. Командные строки дочерних процессов не показываются пользователю. При ошибке без обычных сообщений апдейтера используется последний вывод процесса, например исключение Python. Недоступность systemd или журнала отображается в интерфейсе. Апдейтер дополняет журнал сообщениями об основных этапах.

Тот же механизм используется после передачи пакета с флешки. Существующие проверки занятости, checksum, сбойного тега, импорта, VERSION и условия отката не меняются. Новый интерфейс доступен после установки обновления; уже запущенный старый GUI не меняется от публикации релиза.
