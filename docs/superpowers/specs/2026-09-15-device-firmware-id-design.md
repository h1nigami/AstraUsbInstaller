# ID регистратора как источник идентификации

## Цель и границы

Оператор задаёт каждому регистратору уникальный положительный числовой ID в самом устройстве. Станция считывает этот ID из данных регистратора и использует его напрямую в Python v1 и Avalonia v2. Локальный порядковый номер больше не подменяет ID устройства.

После определения устройства на главном экране показывается только числовой ID. Пока ID читается, плитка показывает состояние «Определение ID», без метки тома и пользовательского имени. Архив нового сеанса находится в `Device{id}`, где `{id}` равен прочитанному ID. Пользовательское имя может оставаться во вкладке «Устройства» и в поиске, но не влияет на идентификацию, главный экран и путь архива.

## Чтение ID

Станция читает `#ID:` из журнала регистратора в `LOG` и номер устройства из самого свежего распознаваемого имени записи в `DCIM`. Для Avalonia используются существующий `RecordingName` и проверенная историческая реализация чтения журнала. Python получает те же правила разбора. Станция не читает видео целиком ради ID.

Принимается только ASCII-десятичное число от 1 до `9223372036854775807`. Ноль, пустое значение, неверный формат и число вне диапазона не считаются ID. Если оба источника дали допустимые, но разные ID, станция останавливает регистрацию с ошибкой. Если допустимый ID нашёлся только в одном источнике, он используется. Если не нашёлся ни в одном, копирование не начинается. Если существующий журнал или запись нельзя прочитать, станция сообщает об ошибке чтения и не угадывает ID по оставшемуся источнику.

До начала сканирования, копирования и автоудаления станция резервирует прочитанный ID за подключённым носителем. Второй одновременно подключённый носитель с тем же ID получает ошибку. Если устройства с одинаковым ID подключаются по очереди, станция не может различить их: уникальность ID обеспечивает оператор. Это ограничение показывается в документации, без обещания автоматической проверки.

## База и архив

Для новых устройств `devices.id` равен ID регистратора. Колонка `devices.id_source TEXT DEFAULT ''` хранит `device` для новой записи. При повторном подключении используется только строка с `id_source = 'device'` и тем же ID. Если этот числовой ключ уже занят старой записью без такой отметки, станция сообщает о конфликте и ничего не копирует. Она не переиспользует чужую запись по USB-серийнику, метке тома, имени или старому маркеру. USB-серийник может совпадать у разных экземпляров и остаётся только служебным сведением; при совпадении схема `serial UNIQUE` допускает служебный суффикс с ID.

Python и Avalonia используют одну схему SQLite для этого признака и одинаковую проверку конфликта. В `backups.dest_path` и журнале собранных файлов остаются фактические пути нового сеанса. Старые строки базы и папки вроде `Device123456`, созданные по прежнему Astra ID, не переименовываются автоматически: надёжной связи с ID регистратора у них может не быть. Ручной перенос старых архивов не входит в эту задачу.

## Маркеры и безопасность

Станция прекращает чтение и запись `.astra_id` и `.bestcam_id` как способов идентификации. Существующие файлы на носителях остаются нетронутыми и исключаются из копирования и сканирования как служебные. Маркер диска назначения и маркер активности копирования сохраняются: они защищают от записи не на тот диск и от обновления во время копирования.

При отсутствии ID, противоречии источников, занятом ID или конфликте с прежней записью базы станция показывает ошибку на плитке устройства. В этих случаях она не создаёт папку архива, не копирует файлы и не удаляет исходные видео. Пропажа носителя во время чтения ID также отменяет регистрацию. Существующее правило удаления только успешно сохранённых видео после штатной выгрузки остаётся неизменным.

## Проверка

Тесты обеих версий проверяют ID из журнала, ID из имени записи, совпадение двух источников, противоречие, отсутствие ID, неверный ID и два одновременно подключённых устройства с одним ID. Сквозная проверка должна подтвердить одинаковое число на главном экране, в `devices.id` и в папке `Device{id}`, а также отсутствие новых файлов-маркеров на источнике. При ошибке проверяются отсутствие копирования и автоудаления. Старые архивы и служебные маркеры не должны удаляться или попадать в новый архив.
