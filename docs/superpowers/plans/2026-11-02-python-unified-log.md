# Единый журнал Python-станции: план

> Исполнение: superpowers:executing-plans, самостоятельно в текущем чате. Требование одного журнала задано пользователем, дополнительных согласований не требуется.

**Цель:** один файл содержит сведения о работе станции и причинах неудачного обновления.

**Архитектура:** расширить существующий журнал `usb_monitor.py`; включить его в точке входа апдейтера, сохранить вывод дочерних команд. Экспортировать один файл.

**Стек:** Python stdlib, unittest, systemd, bash.

**Спецификация:** `docs/superpowers/specs/2026-11-02-python-unified-log-design.md`.

## Ограничения и проверка

- Сбой записи и недоступность systemd не прерывают работу.
- Системные команды ограничены по времени и числу записей; сообщения ядра отфильтрованы по устройствам и завершению процессов.
- Вывод таймаута установщика сохраняется; неудачный тег и откат остаются без изменения.
- Возврат диска и экспорт включают запасной журнал, не удаляя его из-под другого процесса.
- Экспорт в корень самого архива не затирает действующий журнал; повторный экспорт имеет уникальное имя.

## Выполненные проверки

- Исходный Windows-набор: 375 тестов, OK, 29 пропусков.
- Итоговый Windows-набор: 386 тестов, OK, 30 пропусков.
- Итоговый Linux-набор, Python 3.12, curl и Tk: 386 тестов, OK, 1 пропуск (требует дисплей).
- `py_compile` четырёх модулей, `bash -n` четырёх скриптов и `git diff --check`: OK.
- Проверены реальными дочерними процессами stderr/stdout, таймаут и ошибка импорта GUI до запуска интерфейса.
- При первом Linux-прогоне тестовая среда была неполной: отсутствовал curl, каталог исходников был только для чтения. Повторный полный прогон выполнен с зависимостями и отдельной записываемой копией исходников внутри контейнера.
- Ошибка закрытого файла журнала сначала воспроизведена тестом, затем исправлена без изменения запуска команды.
- Независимое read-only ревью текущего диффа не оставило существенных замечаний. Физические отключения диска и конкретная станция не проверялись. Существующий подсчёт размера архива при экспорте не менялся; на большом или неисправном диске он может быть долгим.

Решение: непрерывный сбор всех сообщений ОС не добавляется. Снимки обеих служб и сообщений ядра дополняют прямую запись Python и установщика. Это сохраняет существующий запуск и ограничивает объём диагностики.

Релиз и установка на физической станции в эту проверку не входят.
