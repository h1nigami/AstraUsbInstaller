# Исправления по ревью v1.15

Основание: `docs/review/v115-before-fixes.md`. Пользователь разрешил исправления, но запретил выкладку до отдельной команды.

Цель: устранить R1–R12 в исходниках кандидата и оставить проверяемую ветку для следующего выпуска. Стек: Python stdlib, Tkinter, systemd, bash. Новые зависимости не добавлять.

## Решения

- Работа в отдельной ветке от тега v1.15 с перенесёнными проверенными изменениями кандидата. VERSION не менять вручную. Новый тег выбирается при разрешённом выпуске; повторная публикация v1.15 не планируется.
- Копирование, очистка, сброс и установка используют одну блокировку операций. На Linux это `flock` файла `DB_PATH + '.operations.lock'`: задания берут shared, обслуживание exclusive, конфликт вызывает отказ без ожидания и без изменения данных. На Windows нужны эквивалентные гарантии внутри процесса; updater/systemd только Linux.
- Очистка сохраняет возрастной критерий записей. Во время копирования очистка и сброс отказывают до изменения файлов или БД. Это исключает гонку без молчаливого изменения срока хранения.
- GUI получает подтверждение остановки от движка, включая очередь, монтирование и повторные попытки. Ошибка размонтирования запрещает сообщение о безопасном извлечении. Чужое монтирование не отключается автоматически.
- Повреждённые настройки остаются на диске, не превращаются в стандартный пароль. Изменения настроек объединяются под общей блокировкой и записываются атомарно.

## Контракты между задачами

- `operation_guard(exclusive=False)` в usb_monitor: context manager, неблокирующий конфликт вызывает OSError; Linux межпроцессная защита. Файл определяется из актуального DB_PATH.
- `safe_removal_status()` в usb_monitor возвращает `(state, message)`, state из `running`, `stopping`, `blocked`, `ready`. GUI использует его вместо предположений по плиткам.
- `_load_config(path=None)` возвращает словарь; повреждение отмечается ключом `_config_unreadable`.
- `update_config(updates, remove_keys=(), path=None, repair=False)` возвращает bool, атомарно применяет только переданные изменения к актуальному файлу. `repair=True` допустим только для явного восстановления после ошибки, не для обычной смены параметра.
- `_save_config(cfg, path=None)` остаётся совместимым для существующих тестов/внутренних вызовов; рабочие read-modify-write callers переходят на update_config.

## Проверка

Каждая задача: падающий тест, минимальное исправление, проход соответствующего набора. Общий запуск: `python3 -m unittest discover -s tests -v`; синтаксис: `python3 -m py_compile gui.py usb_monitor.py main.py updater.py`; shell: `bash -n` для четырёх скриптов.

Обязательные сценарии: системное назначение сброса сохраняет файлы и БД; конфликт ID не копирует; pause/resume продолжает только прерванные карты; queued/retry/EBUSY не разрешают извлечение; exclusive обслуживание исключает новых workers; повреждение JSON не даёт пароль exit; сто сеансов одной папки дают один обход; ошибка сброса отображается; установщик не меняет C#.
