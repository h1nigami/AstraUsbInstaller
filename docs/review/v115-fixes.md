# Исправления после ревью Python v1.15

Дата: 21 сентября 2026 года. Ветка: `codex/v115-review-fixes`.

Основа: тег `v1.15` и исходники проверенного кандидата с SHA256
`ce95cd7d9d5665081ab06e6b796d416bfed17eb942381ab0bfa9f390b454f228`.
Исходный отчёт сохранён в `v115-before-fixes.md`; его номера строк относятся
к прежнему кандидату.

## Что изменено

| Замечание | Исправление |
|---|---|
| R1 | Сброс проверяет физический диск, идентичность назначения и обычный файл `.astra_dest`, удерживает каталог открытым и удаляет только настоящие папки `DeviceN`. Проверка выполняется до изменения истории. |
| R2 | Конфликт LOG/DCIM запрещает копирование. Читается актуальный журнал; повреждение и ошибка чтения не заменяются старым ID. |
| R3 | Статус безопасного извлечения сообщает движок. Он учитывает очередь заданий, работающих исполнителей и обслуживание; остановка отменяет ожидание возвращения карты. |
| R4 | Ошибка `umount` сохраняется и запрещает разрешение извлечения. Чужое монтирование требует системного извлечения. |
| R5 | Копирование держит совместную блокировку операций; обновление и установщик требуют исключительную. На Linux проверена межпроцессная блокировка `flock` и передача её дескриптора установщику. |
| R6 | Удалено автоматическое отключение и удаление C# продукта из Python-установщика. |
| R7 | Общая атомарная запись настроек объединяет изменённые поля. Повреждённый конфиг сохраняется, пароль `exit` не подставляется; запись архива запрещена. |
| R8 | Исходники подготовлены в отдельной ветке. Workflow проверяет код выбранного тега, пакует только логотип из `data/` и не перезаписывает вложения. Новый тег нужен при разрешённом выпуске. |
| R9 | Возобновление повторно ставит прерванные задания подключённых карт. Успешные задания не повторяются только из-за снятия остановки. |
| R10 | Очистка, включая ручную очистку устройства, использует исключительную блокировку и проверенное назначение. Удаление ограничено видео в `DeviceN`. |
| R11 | Поиск выбирает уникальные папки, устраняет повторы путей и прекращает устаревший обход внутри циклов. |
| R12 | Текст ошибки передаётся в отложенный callback аргументом. Ошибки SQLite при сбросе тоже показываются оператору. |

Дополнительное независимое ревью обнаружило обход блокировки в ручной
очистке и необработанную ошибку SQLite. Оба случая воспроизведены тестами
и включены в исправления.

Для длительной работы журнал регистратора теперь читается построчно.
Служебный учёт отключённых прерванных устройств и кеш прогресса завершённых
заданий очищаются.

## Границы выпуска

- Станция `192.168.0.41` не изменялась. Публикации, установки и перезапуски
  в рамках этих исправлений не выполнялись.
- Исправления должны получить новый тег `v1.*`: повторная публикация
  `v1.15` не обновит станции с той же версией или с пометкой неудачного тега.
- Старый установленный код не знает новой блокировки. До первого внедрения
  нужно безопасно завершить копирование и остановить старую службу.
  Перед публичным выпуском необходимо подготовить старые станции, чтобы
  их прежние автообновляторы не установили пакет во время копирования.
- Запрет системного диска относится к архиву и экспорту записей. Установка,
  база, конфиг и служебные журналы продолжают записываться на системный диск.
- Возрастная очистка сохраняет исходный смысл: срок считается по времени
  записи файла. После завершения копирования старая запись может быть
  удалена согласно настроенному сроку хранения.
- Локальные проверки не заменяют длительный прогон на Astra с реальными
  USB-устройствами и проверку загрузки станции. Причина прежнего чёрного
  экрана сама по себе этими тестами не установлена.

## Проверки

Полный Linux-прогон на Python 3.12: **257 тестов прошли, без пропусков**,
14,141 секунды. Среда WSL с доступными Tkinter и bash; подключение к станции
не использовалось. Журнал: `tests-linux.log` рядом с этим отчётом.

Проверены `py_compile` для `gui.py`, `usb_monitor.py`, `main.py`, `updater.py`,
`bash -n` отдельно для `install_native.sh`, `start_native.sh`, `update.sh`,
`diagnose.sh`, а также `git diff --check`.

Linux-набор включает реальный межпроцессный `flock`, отказ установщика при
занятом архиве, передачу дескриптора, регрессии GUI без графического экрана,
остановку очереди, возобновление той же карты, запрет системного назначения,
сохранность оригинала при сбое записи и конфликт ID. Монтирование настоящих
USB-носителей, systemd и графический сеанс Astra здесь не испытывались.

Условия обоих release workflow проверены по исходникам: Python ограничен
стабильными тегами `v1.*`, оба задания C# ограничены `v2.*`, включая ручной
запуск. GitHub Actions не запускались; фактические вложения и выбор пакета
нужно проверить после разрешённой публикации.
