# Astra USB Installer / USB Backup Manager

Автоматический мониторинг USB-устройств, создание резервных копий файлов и управление устройствами через GUI.

## Возможности

- Автоопределение новых USB-устройств (Linux / Windows)
- Монтирование, сканирование и инкрементальное копирование файлов
- Одна папка на устройство: `USB_Backups/Device1/`, докачка только новых/изменённых файлов
- Запись `.astra_id` на USB для постоянной идентификации устройства
- GUI на Tkinter (fullscreen, вкладки: поиск, устройства, workers, настройки)
- Выход из GUI только по паролю (смена пароля через вкладку настроек)
- Headless-режим (Docker, сервер без экрана)
- Поддержка нескольких USB одновременно (ThreadPoolExecutor)
- SQLite-база: история устройств и бэкапов
- Поиск по дате, устройству, человеку

## Кроссплатформенная версия (BestCam Station 2.0)

Программа станции переписана на .NET и Avalonia: Python и Docker для неё не
нужны, вся программа приходит одним каталогом. Исходники лежат в `avalonia/`,
сборки под Linux, Windows и macOS выходят отдельными релизами с тегами вида
`v2.x`.

Поставить на станцию одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/h1nigami/AstraUsbInstaller/master/avalonia/install.sh | sudo bash
```

Скрипт определяет разрядность, забирает пакет нужного релиза, сверяет
контрольную сумму и ставит его. Нужен конкретный релиз, в том числе
предварительный: передайте тег, `... | sudo bash -s -- v2.0.2`.

Без сети на станции скачайте пакет заранее и поставьте его сами:

```bash
sudo apt install ./bestcam-station_2.0.2_amd64.deb
```

Пакет кладёт программу в `/opt/astra-usb-avalonia`, ставит службу киоска,
правило udev против автомонтирования и таймер обновлений. Удаляется
обычным `sudo apt remove bestcam-station`, база станции и записи при этом
остаются. Для Windows в релизе лежит установщик `BestCamStationSetup-*.exe`,
для macOS архив под нужный процессор. Дальше станция
обновляется сама раз в шесть часов: сверяет контрольную сумму, проверяет, что
новая сборка запускается, и при неудаче возвращает прежнюю версию.

Учётная запись администратора `admin`, пароль `888888`, меняется в разделе
«Настройки». Веб-панель выключена по умолчанию, включается там же, адреса
станции в сети показываются рядом с выключателем.

Пока переход не завершён, обе версии живут в одном репозитории и не мешают
друг другу: архивы называются по-разному, и каждый апдейтер берёт только
свой.

## Быстрый старт (Docker)

```bash
docker compose up -d --build
```

Этого достаточно — образ собирается сразу с голосовым стеком (torch + coqui-tts),
поэтому приветствие нанокостюма работает «из коробки». Что нужно знать:

- **Первая сборка большая** (~3 ГБ зависимостей) и идёт несколько минут. Дальше
  всё кэшируется.
- **Модели голоса** (XTTS ~1.8 ГБ, Silero ~60 МБ) скачиваются один раз при
  первом запуске в том `./data` (через `TTS_HOME`), поэтому при пересоздании
  контейнера заново не качаются. Для первого запуска нужен интернет.
- **Точная копия голоса**: положите клип нанокостюма в `data/nanosuit_ref.wav`
  на хосте (папка проброшена в контейнер) — приветствие заговорит этим голосом.
  Без клипа играет нейросетевой голос Silero.
- **Не нужен голос в образе?** Соберите лёгкий вариант:
  `INSTALL_VOICE=0 docker compose up -d --build` (приветствие откатится на espeak).

Для GUI на хосте нужен X-сервер. Docker пробрасывает `/tmp/.X11-unix`; на хосте
может потребоваться один раз разрешить доступ: `xhost +local:`.

## Нативная установка на Astra Linux

Git не нужен — ставится из архива релиза:

```bash
curl -s https://api.github.com/repos/h1nigami/AstraUsbInstaller/releases/latest \
  | grep -o 'https://[^"]*\.tar\.gz' | head -1 \
  | xargs curl -sL -o astra-usb-monitor.tar.gz

mkdir -p ~/astra-usb && tar xzf astra-usb-monitor.tar.gz -C ~/astra-usb
cd ~/astra-usb
./install_native.sh
```

Первая команда всегда берёт последний релиз, версию указывать не нужно.
Подробная инструкция с первой настройкой и полезными командами приложена к
каждому релизу на [странице релизов](https://github.com/h1nigami/AstraUsbInstaller/releases)
и лежит в [`.github/release-install.md`](.github/release-install.md).

Инсталлятор ставит `systemd`-сервис и `udev`-правило для native-mode: новые
USB-носители больше не auto-mount'ятся рабочим столом сами, поэтому поздний
`udisks` mount не может создать второй RW-mount поверх mount'а приложения.
Если потом нужно выбрать **новый** USB-диск как папку назначения, смонтируйте
его вручную один раз в файловом менеджере; уже сохранённый destination
приложение распознаёт и под своим mountpoint'ом.

## Обновления

Версия хранится в файле `VERSION` рядом с `gui.py` (одна строка: тег релиза и
дата) и видна в **Настройки → О программе**. Файл кладёт релизный workflow
GitHub — руками его не редактируют.

`install_native.sh` ставит и включает `astra-usb-update.timer`: он сам, без
участия человека, проверяет `releases/latest` репозитория
`h1nigami/AstraUsbInstaller` (первый раз — через 10 минут после загрузки,
дальше каждые 6 часов) и подтягивает новый релиз, если он есть. При
неудачном обновлении приложение автоматически откатывается на предыдущую
версию. Точки стоят без обслуживания и без сети большую часть времени, и
именно на этот случай таймер и рассчитан — при отсутствии сети он просто
ничего не делает.

**Если приложение установлено из git-клона, а не из релиза** (файла `VERSION`
в исходниках не было), у него нет тега для сравнения — и первый же тик
таймера сочтёт точку требующей обновления и заменит только что поставленную
локальную сборку последним релизом с GitHub. `install_native.sh` предупреждает
об этом в конце установки; если сейчас это не нужно —
`systemctl disable --now astra-usb-update.timer`.

`update.sh` — отдельный ручной способ обновления, для git-клонов
разработчика: подтягивает `origin/master` и переустанавливает через
`install_native.sh`. Ему обязателен каталог `.git`, поэтому из релизного
архива (там `.git` нет) он не работает — это путь только для машин,
поставленных из клона репозитория, а не таймером.

**Если релиз оказался плохим**, повторная публикация того же тега не
поможет: апдейтер помнит, что этот тег уже откатывали, и просто пропускает
его на каждом следующем тике. Чтобы точки подхватили исправление, нужен
новый тег.

## Использование без Docker

```bash
pip install -r requirements.txt
python main.py          # автоопределение: GUI или headless
python usb_monitor.py   # принудительно headless
```

## Пароль на выход

Приложение работает в полноэкранном режиме. Для выхода требуется пароль.

- При первом запуске пароль: `exit`
- Пароль можно сменить во вкладке **Настройки** → **Изменить пароль**
- Хранится в `data/config.json` (файл в `.gitignore`, не попадает в репозиторий)
- Переменная окружения `APP_EXIT_PASSWORD` задаёт пароль при первом запуске

## Инкрементальное копирование

Каждое устройство получает одну папку: `USB_Backups/Device{id}/`.

- При повторном подключении файлы сверяются по размеру и дате изменения
- Неизменённые файлы пропускаются
- Новые файлы копируются
- Изменённые файлы сохраняются с суффиксом даты (старый не удаляется)
- `.astra_id` не копируется

## Голос нанокостюма при запуске

При старте GUI проигрывается приветствие голосом нанокостюма. Источник голоса
выбирается автоматически по убыванию качества:

1. **Точная копия (клонирование голоса, XTTS v2)** — даёт ТОЧНО тот же голос,
   что в игре. Требует один короткий референс-клип реального голоса
   нанокостюма:
   - Возьмите 6–15 секунд чистой речи нанокостюма из русской локализации
     (один-два WAV/MP3, без музыки и шума) и сохраните как
     **`data/nanosuit_ref.wav`** (моно/стерео, любой sample rate).
   - Путь можно переопределить переменной `NANOSUIT_REF_WAV`.
   - Установите движок: `pip install -r requirements-voice.txt`
     (кроссплатформенно: Arch Linux и Windows). При первом запуске скачивается
     модель (~1.8 ГБ).
   - XTTS воспроизведёт фразу «С возвращением, Пророк» этим же голосом. Так
     как референс уже содержит «костюмный» тембр, дополнительные DSP-эффекты
     не накладываются.
2. **Нейросетевой голос Silero** — если референс-клипа нет: живой русский
   мужской голос + «нанокостюмный» эффект. Ставится тем же
   `pip install -r requirements-voice.txt` (модель ~60 МБ скачивается один раз
   в `data/`).
3. **espeak-ng + DSP** — если не установлены опциональные голосовые зависимости.

Все зависимости голоса опциональны: без них приложение работает, просто
приветствие беднее по качеству.

> Лицензия весов XTTS v2 (CPML) — некоммерческая; для личного использования
> подходит.

### Диагностика голоса

Если голос **одинаковый с референс-клипом и без него** — значит клонирование
не запускается и играет запасной движок (Silero). Проверьте, какой движок
реально используется и почему остальные пропущены:

```bash
python gui.py --voice-test
```

Команда печатает выбранный движок и точную причину пропуска клонирования
(например, `coqui-tts unavailable (ModuleNotFoundError: No module named 'TTS')`
— значит `pip install -r requirements-voice.txt` не прошёл).

Полезные переменные окружения:

| Переменная | Значение | Эффект |
|---|---|---|
| `NANOSUIT_VOICE` | `clone` / `silero` / `espeak` / `sapi` | Принудительно один движок — ошибки видны, без тихого отката |
| `NANOSUIT_CLONE_FX` | `1` | Наложить металлический эффект костюма поверх клона (по умолчанию выкл.) |
| `NANOSUIT_REF_WAV` | путь | Свой путь к референс-клипу |

Например, `NANOSUIT_VOICE=clone python gui.py --voice-test` заставит запускаться
только клонирование и покажет реальную ошибку, если оно падает.

#### Частые ошибки клонирования

- **`No module named 'torchaudio'`** — `torchaudio` обязателен для coqui-tts.
  Он уже прописан в `requirements-voice.txt`; переустановите:
  `pip install -r requirements-voice.txt`.
- **`cannot import name 'isin_mps_friendly'`** — установлен `transformers` 5.x,
  где эта функция удалена, а coqui-tts её импортирует. Файл
  `requirements-voice.txt` фиксирует `transformers>=4.57,<5`. Почините так:
  `pip install "transformers>=4.57,<5"` (или переустановите весь файл).
- **XTTS требует Python 3.10–3.12.** На 3.13+ колёса coqui-tts могут не
  встать — используйте поддерживаемую версию Python.

### Голос в Docker

По умолчанию образ собирается **без** голосового стека (чтобы не раздувать его
на ~3 ГБ) — приветствие в контейнере откатывается на espeak. Чтобы вшить полный
голос (torch + coqui-tts) в образ:

```bash
INSTALL_VOICE=1 docker compose build
# или: docker build --build-arg INSTALL_VOICE=1 -t astra-usb .
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `USB_BACKUP_DEST` | `./USB_Backups` | Куда сохранять бэкапы |
| `NANOSUIT_REF_WAV` | `./data/nanosuit_ref.wav` | Референс-клип для клонирования голоса |
| `USB_DB_PATH` | `./data/devices.db` | Путь к SQLite БД |
| `USB_MAX_WORKERS` | `10` | Потоков для параллельной работы |
| `USB_DEBUG` | `0` | Включить отладку (1) |
| `DISPLAY` | `:0` | X11 display для GUI |

## Структура проекта

- `usb_monitor.py` — ядро: мониторинг, монтирование, копирование, SQLite
- `gui.py` — графический интерфейс (Tkinter)
- `main.py` — точка входа (GUI → headless fallback)
- `updater.py` — автообновление с релизов GitHub, запускается systemd-таймером
- `install_native.sh` — установка на Astra Linux без Docker
- `update.sh` — ручное обновление для git-клонов
- `start.sh` — entrypoint для Docker
- `docker-compose.yml` — продакшн-развёртывание
- `Dockerfile` — сборка образа
- `requirements.txt` — зависимости Python
