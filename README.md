# Astra USB Installer / USB Backup Manager

Автоматический мониторинг USB-устройств, создание резервных копий файлов и управление устройствами через GUI.

## Возможности Python-версии

- Автоопределение новых USB-устройств (Linux / Windows)
- Монтирование, сканирование и инкрементальное копирование файлов
- Одна папка на регистратор: `USB_Backups/Device1234567/`, докачка только новых и изменённых файлов
- ID, назначенный в регистраторе, как постоянный идентификатор
- GUI Python-версии на Tkinter: Загрузка, Поиск, Устройства, Настройки
- Выход из GUI только по паролю (смена пароля через вкладку настроек)
- Headless-режим для запуска без графического интерфейса
- Поддержка нескольких USB одновременно (ThreadPoolExecutor)
- SQLite-база: история устройств и бэкапов
- Поиск по дате, устройству, человеку

### Идентификация регистраторов

Оператор заранее назначает каждому регистратору уникальный положительный
числовой ID. Программа считывает его из `#ID:` в свежем журнале
каталога `LOG` или из номера устройства в имени свежей записи каталога
`DCIM`. В значении после `#ID:` учитываются только первые 7 символов:
например, `1212345-0000000` даёт ID `1212345`. Более короткий номер
используется целиком. Принимаются только ASCII-цифры и числа от 1 до
`9223372036854775807`. Если два источника называют разные ID, обработка
останавливается. Без допустимого ID станция тоже не начинает копирование и
автоудаление.

Прочитанный ID напрямую становится `devices.id` в локальной базе. Новая
строка помечается `id_source = 'device'`. Если это число занято прежней
записью базы без такой отметки, станция сообщает о конфликте и не использует
старую строку. Совпадающий заводской USB-серийник хранится лишь как служебное
сведение и не объединяет регистраторы.

Одновременно подключённые носители с одинаковым ID не выгружаются вместе:
второй получает ошибку без копирования и удаления видео. Если такие устройства
подключить по очереди, станция не сможет их различить. Уникальность ID
обеспечивает оператор.

Архив находится в `Device{id}`, например ID 1234567 соответствует папке
`Device1234567`. После определения номера главный экран
показывает только `1234567`; пока номер читается, пишет «Определение ID».
Пользовательское имя остаётся во вкладке «Устройства» и поиске, но не меняет
ID и папку.
На Linux служба передаёт владельцу и группе корня архива только прямые папки
с положительным числовым именем `DeviceN`. Проверка выполняется при запуске и
после копирования.

Станция больше не читает и не создаёт `.astra_id` и `.bestcam_id` для
идентификации. Ранее записанные маркеры остаются на носителе и не попадают в
архив. Старые строки базы и папки не переименовываются автоматически, так как
их прежний локальный номер мог не совпадать с ID регистратора.

## Нативная установка на Astra Linux

Git не нужен. Скачайте Python-архив и его контрольную сумму из одного релиза:

```bash
TAG=v1.7
ARCHIVE="astra-usb-monitor-${TAG}.tar.gz"
BASE="https://github.com/h1nigami/AstraUsbInstaller/releases/download/${TAG}"
curl -fL -o "$ARCHIVE" "$BASE/$ARCHIVE" && \
  curl -fL -o "$ARCHIVE.sha256" "$BASE/$ARCHIVE.sha256" && \
  sha256sum -c "$ARCHIVE.sha256" && \
  mkdir -p ~/astra-usb && \
  tar xzf "$ARCHIVE" -C ~/astra-usb && \
  cd ~/astra-usb && bash install_native.sh
```

Продолжайте установку только после успешной проверки SHA256. Нужный тег
можно выбрать на [странице релизов](https://github.com/h1nigami/AstraUsbInstaller/releases).
Для Python используйте `v1.*`; C#-пакеты относятся к `v2.*`.

Инсталлятор создаёт службу systemd и правило udev, которое запрещает
рабочему столу автоматически монтировать USB-носители. Это предотвращает
двойное монтирование диска на запись. Чтобы выбрать новый диск назначения,
один раз смонтируйте его через файловый менеджер. Сохранённый диск программа
распознаёт и при смене точки монтирования.

## Обновления

Версия хранится в файле `VERSION` рядом с `gui.py` (одна строка: тег релиза и
дата) и видна в **Настройки → О программе**. Файл кладёт релизный workflow
GitHub: руками его не редактируют.

В Python-версии автоматические проверки и установка обновлений отключены.
Обновление запускается оператором в «Настройках»: кнопкой «Проверить
обновления» через интернет или «Обновление с флешки» с архивом
`astra-usb-monitor-<tag>.tar.gz` и его `.sha256` в корне носителя.
Оба способа используют отдельную службу `astra-usb-update.service`.
`install_native.sh` останавливает и удаляет прежний `astra-usb-update.timer`;
новый таймер не создаётся. При неудачном обновлении приложение
автоматически откатывается на предыдущую версию.

Python-апдейтер принимает только стабильные теги `v1.*` и архив
`astra-usb-monitor-<tag>.tar.gz` с точным совпадением тега и своей SHA256.
Чужой релиз пропускается. `latest` закреплён за Python.
Исторические релизы C# сохранены для совместимости старых установок.
Новые версии BestCam Station выпускаются отдельно.

После установки проверяются импорт или запуск сборки, активность службы,
счётчик её перезапусков и установленный `VERSION`. Несовпадение версии
вызывает откат. При отсутствии графической сессии служба ждёт X11;
эта проверка не подтверждает отрисовку интерфейса.

Штатный выход по паролю во время проверки обновления сохраняет новую
версию. Программа остаётся закрытой до запуска ярлыком или перезагрузки.
Обе проверки, в установщике и апдейтере, принимают завершение службы с
кодом 0 и без аварийных перезапусков. Ошибка запуска, ненулевой код,
завершение сигналом, перезапуски и неверный `VERSION` по-прежнему вызывают откат.
При первом переходе на эту реализацию уже работающий старый апдейтер
заканчивает свою попытку по прежним правилам.

**Если приложение установлено из git-клона, а не из релиза** (файла `VERSION`
в исходниках не было), установщик пробует определить версию по git-тегу.
Если тег определить не удалось, версия может не отображаться. Ручная
проверка обновлений в таком случае может заменить локальную сборку
последним стабильным Python-релизом с GitHub.

`update.sh`: отдельный ручной способ обновления, для git-клонов
разработчика: подтягивает `origin/master` и переустанавливает через
`install_native.sh`. Ему обязателен каталог `.git`, поэтому из релизного
архива (там `.git` нет) он не работает: это путь только для машин,
поставленных из клона репозитория.

**Python и C# устанавливаются независимо.** Установщик Python не удаляет
пакет, службы, настройки и данные `astra-usb-avalonia`. Переход между
продуктами выполняется отдельно по решению оператора. Одновременную работу
двух программ с одними картами следует исключить при настройке станции.

Копирование использует общую блокировку с очисткой, сбросом и установкой.
Занятое приложение откладывает обновление; установщик удерживает блокировку
до завершения установки. Эта защита действует для версий, поддерживающих
блокировку. При первом переходе со старой v1.15 копирование нужно безопасно
завершить, остановить службу и только затем устанавливать исправление.

**Если релиз оказался плохим**, повторная публикация того же тега не
поможет: апдейтер помнит, что этот тег уже откатывали, и просто пропускает
его на каждом следующем тике. Чтобы точки подхватили исправление, нужен
новый тег.

Исправления v1.15 выпускаются под новым тегом `v1.*`. Сборка проверяет
исходники выбранного тега и не перезаписывает существующие вложения релиза.

### Журнал Python-станции

В «Настройки → О программе» показываются ход обновления и результат последней
попытки с временем сообщения. Видны доступная версия, загрузка, установка,
проверка запуска, откат и причины пропуска, включая занятость станции и
ранее неудачный релиз. Состояние читается из службы и её журнала в фоне,
включая обновление с флешки. После перезапуска GUI результат восстанавливается.
Если служба не начала новую попытку или журнал недоступен, это указывается явно.

В корне выбранного архива находится `astra-usb-monitor.log`. В него пишутся
работа программы, проверка обновлений, причины пропуска релиза и отката,
вывод установщика и ошибки импорта Python. В начале проверки обновления
указываются версия станции и PID процесса.

При запуске интерфейса, завершении проверки обновления и выгрузке журнала
добавляются версия, тег неудачного обновления, состояния обеих служб,
последние 200 сообщений их общего журнала и относящиеся к USB, дискам и
завершению процессов записи среди последних 200 сообщений ядра.
Эти сведения собираются автоматически, команды на станции не нужны.
Если systemd недоступен, причина также записывается в файл.

Пока диск архива отключён или недоступен для записи, журнал сохраняется
внутри приложения. После возвращения диска накопленные записи добавляются
в `astra-usb-monitor.log`. Заголовки источников позволяют отличить сохранённые
фрагменты; они могут повторяться после перезапуска. При открытии журнала
размером больше 10 МиБ сохраняется его последняя половина.

«Настройки → Выгрузить логи» сохраняет один файл
`astra-usb-monitor-<дата>_<время>-<суффикс>.log` прямо в выбранном каталоге.
Внутри находятся рабочие записи, запасной журнал, диагностическая сводка и
системные сообщения. Отдельные папки, `version.txt` и `summary.txt` не создаются.
Журнал может содержать пути файлов и сведения об устройствах, уже выведенные
программой; сводка содержит только счётчики.

## Запуск Python из исходников

```bash
pip install -r requirements.txt
python main.py          # автоопределение: GUI или headless
python usb_monitor.py   # принудительно headless
```

В «Настройках» Python-версии можно задать количество гнёзд от 1 до 12.
По умолчанию их 10. Для станции с 8 гнёздами выберите 8 и нажмите
«Сохранить»: карточки на вкладке «Загрузка» перестроятся сразу,
а выбранное число сохранится после перезапуска.
Если подключить больше регистраторов, чем задано гнёзд, копирование
продолжится для всех. На экране появится предупреждение о нехватке карточек.
После подтверждённого отключения в освободившейся карточке сразу появится
один из скрытых регистраторов. Короткое переподключение USB карточку сохраняет.

## Пароль Python-версии

Приложение работает в полноэкранном режиме. Для выхода требуется пароль.

- При первом запуске пароль: `exit`
- Пароль можно сменить во вкладке **Настройки** → **Изменить пароль**
- Хранится в `data/config.json` (файл в `.gitignore`, не попадает в репозиторий)
- Переменная окружения `APP_EXIT_PASSWORD` задаёт пароль при первом запуске

Если существующий файл настроек повреждён, программа запрещает доступ
через стандартный пароль и сохраняет повреждённый файл. Администратор
должен восстановить корректный `data/config.json` из резервной копии.
Обычное сохранение настроек атомарно объединяет изменённые поля.

## Остановка и защита архива

После остановки копирования подключение новой карты не запускает задание.
Разрешение извлечь носители появляется только после завершения заданий и
размонтирования. Если размонтирование не удалось или носитель смонтирован
другой программой, интерфейс сообщает причину и не подтверждает безопасность
извлечения. Возобновление повторяет прерванные задания подключённых карт.

На Linux архив должен находиться на отдельном от системы физическом диске.
Проверка назначения выполняется перед записью; исчезновение диска, подмена
пути и отсутствие маркера `.astra_dest` запрещают копирование. Этот запрет
касается файлов архива: база, настройки и установка приложения по-прежнему
используют системный диск.

Очистка и заводской сброс отказывают во время копирования. Сброс требует
проверенного назначения с обычным файлом `.astra_dest` и удаляет только
каталоги архива `DeviceN` с положительным числовым ID. Посторонние файлы
и маркер назначения сохраняются. Возрастной критерий очистки не изменён.

## Инкрементальное копирование

Каждый регистратор выгружается в `USB_Backups/Device{id}/`, где `{id}` задан в устройстве.

- При повторном подключении файлы сверяются по размеру и дате изменения
- Неизменённые файлы пропускаются
- Новые файлы копируются
- Изменённые файлы сохраняются с суффиксом даты (старый не удаляется)
- Старые `.astra_id` и `.bestcam_id` не копируются

## Переменные окружения Python-версии

| Переменная | По умолчанию | Описание |
|---|---|---|
| `USB_BACKUP_DEST` | `./USB_Backups` | Куда сохранять бэкапы |
| `USB_DB_PATH` | `./data/devices.db` | Путь к SQLite БД |
| `USB_MAX_WORKERS` | `10` | Потоков для параллельной работы |
| `USB_DEBUG` | `0` | Включить отладку (1) |
| `USB_MOUNT_GRACE` | `4` | Сколько секунд ждать существующее системное монтирование |
| `APP_EXIT_PASSWORD` | `exit` | Начальный пароль Python-версии |
| `DISPLAY` | Из окружения | Дисплей X11 для GUI |

## Структура проекта

- `usb_monitor.py`: ядро: мониторинг, монтирование, копирование, SQLite
- `gui.py`: графический интерфейс (Tkinter)
- `main.py`: точка входа (GUI → headless fallback)
- `updater.py`: обновление вручную и с флешки через отдельную службу systemd
- `install_native.sh`: установка на Astra Linux
- `update.sh`: ручное обновление для git-клонов
- `requirements.txt`: зависимости Python

## Проверки для разработчика

```bash
python3 -m py_compile gui.py usb_monitor.py main.py updater.py
python3 -m unittest discover -s tests -v
```

Python-набор рассчитан на Linux; проверки Tkinter требуют установленного
GUI-модуля. Изолированные сценарии установки C# описаны в
одноразовом Docker-контейнере.
