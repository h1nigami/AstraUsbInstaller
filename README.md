# Astra USB Installer / USB Backup Manager

Автоматический мониторинг USB-устройств, создание резервных копий файлов и управление устройствами через GUI.

## Возможности Python-версии

- Автоопределение новых USB-устройств (Linux / Windows)
- Монтирование, сканирование и инкрементальное копирование файлов
- Одна папка на устройство: `USB_Backups/Device1/`, докачка только новых/изменённых файлов
- `.astra_id` на USB как единственный постоянный идентификатор устройства
- GUI Python-версии на Tkinter: Загрузка, Поиск, Устройства, Настройки
- Выход из GUI только по паролю (смена пароля через вкладку настроек)
- Headless-режим для запуска без графического интерфейса
- Поддержка нескольких USB одновременно (ThreadPoolExecutor)
- SQLite-база: история устройств и бэкапов
- Поиск по дате, устройству, человеку

### Идентификация регистраторов

Python и Avalonia используют положительное целое число из `.astra_id` как
единственный ID носителя. Если файла нет, станция создаёт новую строку в
локальной таблице `devices`, получает следующий `devices.id` с
`AUTOINCREMENT`, записывает номер в `.astra_id` и проверяет запись до начала
копирования. Совпадающий заводской USB-серийник сохраняется как служебная
информация и не объединяет разные носители.

Avalonia читает `.bestcam_id` только при одноразовом переносе. Если
`.astra_id` отсутствует, старый маркер должен однозначно указывать на одну
существующую запись локальной базы. Тогда её `devices.id` записывается в
`.astra_id`. Неизвестный или неоднозначный `.bestcam_id` не определяет ID:
носитель получает новый локальный номер.

Одновременно подключённые носители с одинаковым `.astra_id` не
перенумеровываются. Первый сохраняет номер, а второй получает ошибку. Станция
не меняет его маркер, не копирует файлы и не удаляет исходные видео.
Повреждённый `.astra_id` также останавливает обработку без замены файла.

Архив такого носителя находится в `Device{astra_id}`, например Astra ID 7
соответствует папке `Device7`. Основной экран обеих версий показывает
`Astra ID 7`; заданное пользователем имя выводится рядом и не влияет на папку.
На Linux служба передаёт владельцу и группе корня архива только прямые папки
с положительным числовым именем `DeviceN`. Проверка выполняется при запуске и
после копирования.

В Python удаление `.astra_id` приводит к выдаче нового локального номера.
Avalonia восстановит прежний `devices.id`, если на носителе сохранился
`.bestcam_id`, однозначно связанный с одной записью локальной базы. После
форматирования или без такой связи носитель получает новый номер. Уже смешанные
архивы программа автоматически не разделяет.

## C# / Avalonia: BestCam Station

Программа станции написана на .NET и Avalonia и поставляется вместе
с runtime .NET. Исходники лежат в `avalonia/`,
сборки под Linux, Windows и macOS выходят отдельными релизами с тегами вида
`v2.x`.

Поставить на станцию одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/h1nigami/AstraUsbInstaller/master/avalonia/install.sh | sudo bash -s -- v2.0.3
```

Указывайте тег C#-релиза явно: общий `latest` используется Python-версией.
В примере выбран опубликованный `v2.0.3`. Скрипт определяет архитектуру
Linux, скачивает пакет и устанавливает его через apt.

Без сети на станции скачайте пакет заранее и поставьте его сами:

```bash
sudo apt install ./bestcam-station_2.0.3_amd64.deb
```

Пакет кладёт программу в `/opt/astra-usb-avalonia`, ставит службу киоска,
правило udev против автомонтирования и таймер обновлений. Удаляется
обычным `sudo apt remove bestcam-station`, база станции и записи при этом
остаются. Для Windows в релизе лежит установщик `BestCamStationSetup-*.exe`,
для macOS архив под нужный процессор. Windows и macOS обновляются вручную.
На Linux установлен таймер; особенности перехода со старого C#-апдейтера
описаны в разделе «Обновления».

Учётная запись администратора `admin`, пароль `888888`, меняется в разделе
«Настройки». Веб-панель выключена по умолчанию, включается там же, адреса
станции в сети показываются рядом с выключателем.

Python и C# выпускаются отдельно. На одной станции используйте одну
версию: оба приложения работают с одними USB-устройствами и экраном.

## Нативная установка на Astra Linux

Git не нужен. Скачайте Python-архив и его контрольную сумму из одного релиза:

```bash
TAG=v1.7
ARCHIVE="astra-usb-monitor-${TAG}.tar.gz"
BASE="https://github.com/h1nigami/AstraUsbInstaller/releases/download/${TAG}"
curl -fL -o "$ARCHIVE" "$BASE/$ARCHIVE" && \
  curl -fL -o "$ARCHIVE.sha256" "$BASE/$ARCHIVE.sha256" && \
  sha256sum -c "$ARCHIVE.sha256" && \
  mkdir -p ~/astra-usb && \
  tar xzf "$ARCHIVE" -C ~/astra-usb && \
  cd ~/astra-usb && bash install_native.sh
```

Продолжайте установку только после успешной проверки SHA256. Нужный тег
можно выбрать на [странице релизов](https://github.com/h1nigami/AstraUsbInstaller/releases).
Для Python используйте `v1.*`; C#-пакеты относятся к `v2.*`.

Инсталлятор создаёт службу systemd и правило udev, которое запрещает
рабочему столу автоматически монтировать USB-носители. Это предотвращает
двойное монтирование диска на запись. Чтобы выбрать новый диск назначения,
один раз смонтируйте его через файловый менеджер. Сохранённый диск программа
распознаёт и при смене точки монтирования.

## Обновления

Версия хранится в файле `VERSION` рядом с `gui.py` (одна строка: тег релиза и
дата) и видна в **Настройки → О программе**. Файл кладёт релизный workflow
GitHub: руками его не редактируют.

`install_native.sh` ставит и включает `astra-usb-update.timer`: он сам, без
участия человека, проверяет `releases/latest` репозитория
`h1nigami/AstraUsbInstaller` (первый раз: через 10 минут после загрузки,
дальше каждые 6 часов) и подтягивает новый релиз, если он есть. При
неудачном обновлении приложение автоматически откатывается на предыдущую
версию. Точки стоят без обслуживания и без сети большую часть времени, и
именно на этот случай таймер и рассчитан: при отсутствии сети он просто
ничего не делает.

Python-апдейтер принимает только стабильные теги `v1.*` и архив
`astra-usb-monitor-<tag>.tar.gz` с точным совпадением тега и своей SHA256.
C#-апдейтер в текущих исходниках принимает только `v2.*` и `bestcam-station-<tag>-<rid>.tar.gz`.
Чужой релиз пропускается. `latest` закреплён за Python. C# публикуется
как prerelease; обновлённый C#-апдейтер ищет готовую сборку `v2.*` своей
платформы в списке релизов. Для старого C#-апдейтера первая установка
исправленной версии выполняется по явно указанному тегу после её отдельного
выпуска. Изменения C#-апдейтера не доставляются Python-релизом `v1.7`.
Эти ограничения действуют в обновлённых апдейтерах; старые установки
по-прежнему требуют, чтобы в релизах не смешивались продукты.

После установки проверяются импорт или запуск сборки, активность службы,
счётчик её перезапусков и установленный `VERSION`. Несовпадение версии
вызывает откат. При отсутствии графической сессии служба ждёт X11;
эта проверка не подтверждает отрисовку интерфейса.

**Если приложение установлено из git-клона, а не из релиза** (файла `VERSION`
в исходниках не было), у него нет тега для сравнения: и первый же тик
таймера сочтёт точку требующей обновления и заменит только что поставленную
локальную сборку последним релизом с GitHub. `install_native.sh` предупреждает
об этом в конце установки; если сейчас это не нужно ,
`systemctl disable --now astra-usb-update.timer`.

`update.sh`: отдельный ручной способ обновления, для git-клонов
разработчика: подтягивает `origin/master` и переустанавливает через
`install_native.sh`. Ему обязателен каталог `.git`, поэтому из релизного
архива (там `.git` нет) он не работает: это путь только для машин,
поставленных из клона репозитория, а не таймером.

**Станция BestCam на той же машине выключается при установке.** Если рядом с
Python-версией оказалась кроссплатформенная станция (`astra-usb-avalonia`),
`install_native.sh` снимает её пакет через apt, убирает службы и правило udev,
а каталог с базой и записями оставляет рядом под именем
`/opt/astra-usb-avalonia.removed.<дата>`. Ничего не удаляется безвозвратно,
забрать данные оттуда можно в любой момент. Держать два киоска на одной
станции нельзя: они делят экран и одни и те же карты, и какая из программ
заберёт флешку: как повезёт.

**Если релиз оказался плохим**, повторная публикация того же тега не
поможет: апдейтер помнит, что этот тег уже откатывали, и просто пропускает
его на каждом следующем тике. Чтобы точки подхватили исправление, нужен
новый тег.

## Запуск Python из исходников

```bash
pip install -r requirements.txt
python main.py          # автоопределение: GUI или headless
python usb_monitor.py   # принудительно headless
```

## Пароль Python-версии

Приложение работает в полноэкранном режиме. Для выхода требуется пароль.

- При первом запуске пароль: `exit`
- Пароль можно сменить во вкладке **Настройки** → **Изменить пароль**
- Хранится в `data/config.json` (файл в `.gitignore`, не попадает в репозиторий)
- Переменная окружения `APP_EXIT_PASSWORD` задаёт пароль при первом запуске

## Инкрементальное копирование

Каждое устройство получает одну папку: `USB_Backups/Device{astra_id}/`.

- При повторном подключении файлы сверяются по размеру и дате изменения
- Неизменённые файлы пропускаются
- Новые файлы копируются
- Изменённые файлы сохраняются с суффиксом даты (старый не удаляется)
- `.astra_id` не копируется

## Переменные окружения Python-версии

| Переменная | По умолчанию | Описание |
|---|---|---|
| `USB_BACKUP_DEST` | `./USB_Backups` | Куда сохранять бэкапы |
| `USB_DB_PATH` | `./data/devices.db` | Путь к SQLite БД |
| `USB_MAX_WORKERS` | `10` | Потоков для параллельной работы |
| `USB_DEBUG` | `0` | Включить отладку (1) |
| `USB_MOUNT_GRACE` | `4` | Сколько секунд ждать существующее системное монтирование |
| `APP_EXIT_PASSWORD` | `exit` | Начальный пароль Python-версии |
| `DISPLAY` | Из окружения | Дисплей X11 для GUI |

## Структура проекта

- `usb_monitor.py`: ядро: мониторинг, монтирование, копирование, SQLite
- `gui.py`: графический интерфейс (Tkinter)
- `main.py`: точка входа (GUI → headless fallback)
- `updater.py`: автообновление с релизов GitHub, запускается systemd-таймером
- `install_native.sh`: установка на Astra Linux
- `update.sh`: ручное обновление для git-клонов
- `requirements.txt`: зависимости Python

## Проверки для разработчика

```bash
python3 -m py_compile gui.py usb_monitor.py main.py updater.py
python3 -m unittest discover -s tests -v
dotnet test avalonia/AstraUsb.Tests/AstraUsb.Tests.csproj -c Release
```

Python-набор рассчитан на Linux; проверки Tkinter требуют установленного
GUI-модуля. Изолированные сценарии установки C# описаны в
`avalonia/AstraUsb.Tests/updater-integration.sh` и запускаются только в
одноразовом Docker-контейнере.
